# Зв'язок зі Stag без ноутбука і аналіз з дороги — план і знахідки (2026-11-16)

Мета: з одного телефона в дорозі писати ELM (трими) **і** дані Stag (тиск газу, Б, Г, статус газ/бензин), а
корекції множника отримувати одразу — без ноутбука в машині. **Запис у контролер — завжди вручну власником**
(AC STAG / StagMobile); жоден наш інструмент у контролер не пише.

## 1. Що є

- **Контролер:** STAG-4 QBOX **BASIC**, прошивка 2.14.2, AC STAG 0.64.4 (USB-кабель на ноуті — COM5).
- **Bluetooth-інтерфейс Stag — у власника є** (окремий від ELM).
- **StagMobile** (Google Play, `com.acsa.stagmobile`, рейтинг 3,2): підтримує Q-покоління, у т.ч. QBOX.
  Екрани (скріни зі стору зроблені на Q-BOX **PLUS**): параметри авто, налаштування, калібровка, помилки,
  **карта множника з правкою точок**, автокалібровка (**не натискати** — перезапише множник), автоадаптація,
  осцилограф, OBD, **інформація про авто** (поля «Редуктор», «Диам. сопла»), діагностика, оновлення.
- **OBD-функції (трими в StagMobile, OBD-автоадаптація) — лише PLUS** з OBD-адаптером (мануал Stag, розділ про
  OBD). На BASIC недоступні → трими дає лише наш ELM-логер.
- **ISA-3** на BASIC працює лише з підключеним до Stag проводом лямбди (зараз «Не подключен»). Варіант на весну
  (майстер), але лише поверх нормальної ручної калібровки.
- Публічного API / SDK у StagMobile і AC STAG немає; протокол закритий.

## 2. Протокол Stag — що відомо з форумів

Джерела: lpg-forum.pl «STAG protokół RS232 — zbieranie informacji» (t51729, 2015–2017; власник прочитав обидві
сторінки), elektroda «Interfejs bluetooth do instalacji gazowej STAG 4 lub QBOX» (2019).

- Фізично: **UART (TTL)**; Bluetooth-інтерфейс — прозорий міст (напр. HC-05, SPP). STAG-300 / STAG-4 — 9600 бод,
  QBOX — швидше. На ноуті Bluetooth-інтерфейс видно як COM-порт; на Bluetooth-COM швидкість не має значення.
- Модель «запит — відповідь». Спершу ініціалізація (для STAG-300 згадують `F0 01 01 F2`), відповідь на неї —
  великий блок (сотні байтів, ймовірно всі налаштування), потім запити параметрів.
- **Формат пакета** (STAG 200 / EasyGo; контрольну суму перевірено на всіх 4 прикладах з теми, включно з привітанням):

  ```
  [start] 00 00 [len] [дані … len−1 байт] [cks]
  len  = кількість байтів після нього, включно з cks
  cks  = (сума всіх попередніх байтів пакета) & 0xFF
  ```

  Привітання ПК: `AC 00 00 04 00 00 S C` — `S` (напр. `0x91`) стає стартовим байтом усіх наступних пакетів
  сесії; `C` — звичайна контрольна сума привітання (автор теми вважав його «стоп-байтом», а формулу
  «стоп + len + 3» — правилом; насправді це сума). Приклади:
  `91 00 00 03 52 00 E6` (запит ПК), відповіді на 40 і 35 байтів із суммою `6C` / `B4`.
  Байти 1–2 (`00 00`), ймовірно, старші байти довжини (відповідь на ініціалізацію — сотні байтів) — не перевірено.
- **Код:** koczis виклав Java (`stag_na_forum.zip`, клас `StagEngine.startFetchData()`, парсер
  java-binary-block-parser), читає на ходу часи впорску Б/Г, температури газу й редуктора, тиск газу, MAP,
  навантаження, оберти. **Працює з AC gaz synchro v10; «у v11 щось змінили в протоколі»**; Remaper теж не
  працює з версіями > 10. Вкладення (`log.rar`, `stag_na_forum.zip`) — лише після реєстрації на форумі.
- Висновок: загальна обв'язка пакета в QBOX, найімовірніше, схожа; **команди й розміщення параметрів — свої**,
  треба власний запис трафіку.

## 3. Як записати трафік

### 3a. Ноутбук (основний шлях)
1. Спарити Bluetooth-інтерфейс Stag з ноутбуком (PIN зазвичай `1234` / `0000`), записати номер вихідного COM.
   Перевірити, що AC STAG підключається через нього.
2. Встановити **com0com** (підписаний драйвер для x64) — віртуальна пара; встановлено 2026-11-17: **`COM7 ↔ COM8`** (пара «COM# ↔ COM#» з інсталятора, перейменовувати не треба; запасна CNCA0 ↔ CNCB0 не використовується).
3. `python logger\stag_sniff.py --real COMx --virt COM8` — пересилає байти в обидва боки й пише
   `logs/stag_sniff_*.log` (час, напрямок, hex) + розбір пакетів з перевіркою контрольної суми.
4. AC STAG підключити до **COM7**. Сесія на холостих: монітор (2–3 хв), газ ↔ бензин, трохи обертів,
   карта множника, «Информация об автомобиле», знову монітор. **Нічого не зберігати й не змінювати.**
   Нотатки «екран — що робив» (напр. «оберти 2000», «множник 3,5 мс +4 %») — набирати прямо в консолі сніфера
   + Enter: стають рядками `NOTE` з часом у тому ж лозі (порожній Enter — лічильники трафіку); `--parse`
   показує їх між пакетами. Швидкий запуск: `logger\run_sniff.bat COMx` (віртуальний за замовчуванням COM8).

### 3b. Телефон (журнал HCI)
1. Для розробників → «Журнал HCI-трафіку Bluetooth» → режим **повний** (не фільтрований) → Bluetooth off/on.
2. StagMobile: монітор 2–3 хв, карта множника, інформація про авто; нічого не змінювати.
3. «Звіт про помилку» (Xiaomi: `*#*#5959#*#*`) → з архіву лише `FS/data/misc/bluetooth/logs/btsnoop_hci.log`
   (решта звіту — особисті дані телефона, не відкривати). Після — вимкнути журнал HCI.

### 3c. Тест «ELM-логер + StagMobile одночасно» (5 хв, холості)
Спершу наш логер (Підключити → ● Запис), потім StagMobile на екрані 2–3 хв (педаль, екрани, вимкнений
екран 1 хв), повернутись у дашборд — обидва мають бути живі. Перевірити в zip: колонка `hz` (зараз ~4 Гц;
1 Гц і нижче — погано), перепідключення в `.log`. Наш логер — foreground service; StagMobile тримати на екрані.

## 4. Аналіз з дороги

1. **Зараз — Claude Code з телефона** (вкладка «Code» у програмі Claude або claude.ai/code): репо цього проєкту,
   середовище з setup script `pip install pandas matplotlib || true` (мережа Limited + package managers).
   Доставка логу: (A) Remote Control до ПК, що лишився ввімкненим удома — zip прикріплюється й потрапляє на ПК;
   (B) завантажити файли в `logs/` через github.com; (C) **кнопка «Надіслати в репо» в Android-логері**
   (GitHub API, токен з доступом лише до цього репо) — запланована.
   Прикріпити файл прямо до хмарної сесії документація не описує; пушити краще в окрему гілку.
2. **Далі — офлайн-корекції в Android-логері:** розрахунок k = (1+TTгаз)/(1+TTбенз) по клітинках →
   «точка X мс: було → стало» з порогами «замало даних» / «спершу перевір бензин / тиск». Найкраще разом із
   читанням Stag (справжні Б і тиск).
3. **Опційно — сервер на хостингу власника** + Claude API: аналіз і пояснення з дороги (платно, токен API).
