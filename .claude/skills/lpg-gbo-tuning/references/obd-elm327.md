# OBD-II / ELM327 для налаштування ГБО

Джерело: `research/lpg/04_obd_logging_for_lpg.md` (URL там). [H] кілька/первинні джерела, [M] одне добре джерело або виведення, [L] форум/припущення.

## Методика (що роблять тюнери)
1. **Спершу бензин** (якщо на бензині трими погані — газ не налаштувати). [M]
2. Опційно скинути адаптації, щоб обидва палива стартували з відомого LTFT (Toyota: EFI-запобіжник/клема/Techstream; звичайний «clear DTC» LTFT не скидає). [M]
3. Автокалібровка STAG на прогрітих холостих (лямбда активна, без A/C, світла, керма) → множник 1,2–1,8. [H]
4. Лог бензину по всьому робочому діапазону: рівний газ (< ~80 % педалі), 4–5 передача, ~1000–5000 об/хв. Той самий маршрут на газу. [M]
5. Розбити обидва логи на клітинки (оберти × MAP/LOAD або оберти × Б), середній STFT+LTFT по клітинці й паливу, відкинути клітинки з малою кількістю точок. Фільтр: **PID 03 = 2 (CL)**, ECT ≥ 75–80 °C, |ΔRPM| < 150 і |ΔMAP| < 5 кПа за ~2 с, ≥ 3–20 с після перемикання палива/скидання газу, ≥ 20 точок або 10 с на клітинку. [M]
6. Коригувати тільки стабільні відхилення: рівномірно по всій карті → зсунути всю криву множника; локально → лише ці рядки/стовпці (Кор. оборотов / MAP-корекція). Ітерувати; ціль — трими коливаються біля нуля. [M]

**Розмір корекції** [M, виведено]: ECU множить базовий імпульс на (1+TT), STAG — на множник. Щоб газ потребував тієї ж корекції, що й бензин: **k = (1 + TT_газ) / (1 + TT_бенз)**, TT = (STFT+LTFT)/100. Приклад: бензин +1 %, газ −6 % → k ≈ 0,931 → множник −7 %. Застереження: (а) після виправлення Б на газу подовжиться на той самий коефіцієнт — точка зсувається по осі Б, тож правити смугу, а не одну точку; (б) газова форсунка має сталу затримку відкриття — на коротких імпульсах відсоткова корекція менш точна. Практично: перший крок 60–80 % від розрахункового, потім контроль.

**Куди в STAG:** Множитель (залежність від Б, однакова на всіх обертах) · Кор. оборотов (залежить від обертів) · MAP корр. (оберти × MAP; сюди пише ISA-3/OBD-адаптація, при вимкненій — ручні правки) · по-циліндрові корекції — лише для механічних різниць. Не виправляти одну й ту саму помилку у двох картах. [H/M]

**Підводні камені:** open loop (PID 03 ≠ 2) · накат/fuel cut (PID 03 = 4, мале навантаження при обертах вище холостих) · перехідні (сплески ±15 % — норма) · холодний мотор · холості/короткі імпульси · екстравпорски (поріг відсічки / «інтелектуальна обробка» в STAG) · збагачення верхів великим % псує круїз · підсос/MAF видно й на бензині · дві банки (V-двигуни) — прив'язати форсунки до банків · сезонна суміш пропан/бутан. [H/M]

## PID 03 (fuel system status)
| Значення | Зміст | Для калібровки |
|---|---|---|
| 1 | OL, мотор холодний | ні |
| 2 | **CL**, лямбда в контурі | **так** |
| 4 | OL через навантаження / fuel cut | ні (перевірка збагачення — лише з широкосмуговою λ) |
| 8 | OL через несправність | ні |
| 16 | CL, але датчик зворотного зв'язку з несправністю | з підозрою |

PID 44 (задана λ): на вузькосмуговій у CL = 1,0; < 1,0 разом з PID 03 = 4 → збагачення; як підказка, не вимір. [H/M]

## ELM327 — практика
- Реальна швидкість дешевого BT-клона на CAN: **~20–25 PID/с сумарно**, K-line ~5/с, погані клони ~2,5/с; STN (OBDLink) у рази швидші. На до-CAN авто вузьке місце — сам ECU. [M]
- **Мульти-PID лише на CAN:** до 6 PID в одному запиті mode 01 (1+6 = 7 байтів = один кадр); відповідь часто **багатокадрова** (ISO-TP) і PID можуть іти не в порядку запиту → парсер має знати довжини PID. >6 PID — без відповіді. Деякі клони не тягнуть — тестувати й відкочуватися. python-OBD мульти-PID не вміє. [H]
- **Суфікс кількості відповідей** (`01 0C 1`) — ELM повертається одразу, не чекаючи таймауту (типово AT ST = 0x32 ≈ 200 мс). Для багатокадрових відповідей семантика «1» vs «кількість кадрів» у клонах неоднозначна — безпечніше тримати відповіді в одному кадрі. [H/L]
- **AT AT1** (типово, рекомендовано) — адаптивний таймінг; AT2 агресивніше; AT0 вимкнено. [H]
- **Адресація:** `AT SH 7E0` (лише ECM) + `AT CRA 7E8` (приймати лише від ECM) + `AT H1` (бачити ID відповідача). Без цього з функціональним 7DF суфікс «1» може повернути першого відповідача, не обов'язково двигун. `AT SP 0` — автопошук протоколу; `AT DPN` — який знайдено. [H]
- **Клони:** справжньої v1.5 не існує; «v2.1» часто урізані; версія/чіп мало що гарантують → перевіряти можливості (`?` у відповідь — деградувати). [H/M]
- **Windows:** класичний BT (SPP) → віртуальні COM-порти (вихідний і вхідний — відкривати **вихідний**; PIN 1234/0000). **BLE-адаптери COM-порт не створюють** (потрібен GATT або міст ble-serial). [H]
- STAG PLUS з власним OBD-рідером: на газу може конфліктувати з ELM — вимкнути рідер STAG на час логування. BASIC — немає рідера, конфлікту немає. [H/M]

## Витрата з MAF
**л/год = MAF[г/с] × 3600 / (AFR × λ × ρ[г/л])**; л/100 км = л/год × 100 / швидкість.
- Бензин: AFR 14,7 (E10 ≈ 14,1), ρ ≈ 745 г/л (EN 228: 720–775; 820 з однієї статті — помилка).
- LPG: AFR ≈ 15,4–15,6, ρ 500–580 г/л (≈540 для 40/60).
- λ = 1 у CL; у OL — задана λ (PID 44) або широкосмугова; fuel cut → 0.
- Приклад 10 г/с: бензин 3,29 л/год, LPG 4,30 л/год (+31 % за об'ємом).
- Похибки: калібровка MAF, густина LPG (кілька %), мала частота запису (інтегрувати по реальних мітках часу). Сталий надлишок фактичної витрати > 10–15 % понад очікуване → багаті зони (від'ємні трими на газу), дотриск бензину на газу («Доля бензина»), часті повернення на бензин. [M/L]
