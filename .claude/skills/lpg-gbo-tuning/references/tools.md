# Інструменти: ELM327-логер, аналізатор, парсер `.osc`

Код лежить у `scripts/` цього скіла (у проєкті TotyotaLpgCalibration робоча копія — `logger/`).
Залежності: Python 3.10+, `pyserial`, `pandas`, `matplotlib` (`scripts/requirements.txt`).

**Куди пишуться дані:** у теку проєкту `LPG_ROOT` (змінна оточення) → `logs/`, `analysis/`, а `.osc` шукаються в `stag/osc/`.
Без змінної — тека на рівень вище від скрипта (у проєкті це корінь репозиторію). Запускаючи скрипти прямо зі скіла,
**завжди задавай `LPG_ROOT`** на теку проєкту користувача, інакше логи опиняться всередині скіла.

## 1. Логер

```
python elm_logger.py --list            # COM-порти
python elm_logger.py --probe           # ELM, протокол, підтримувані PID, пробні значення
python elm_logger.py                   # запис (порт шукає сам)
python elm_logger.py --port COM5       # конкретний порт
python elm_logger.py --single          # 1 PID/запит (якщо клон не тягне мульти-PID)
python elm_logger.py --sim             # симулятор
```
Клавіші: `g` газ · `b` бензин · `a`/`s` A/C вкл/викл · `h` траса · `c` місто · `i` холості · `m` позначка (m1, m2…) · `q` вихід. Працюють і в українській розкладці. Вікно логера має бути у фокусі.

Як працює (важливо для інтерпретації):
- Власний драйвер (`elm327.py`), не python-OBD. На CAN пакує PID у групи, що вміщаються в один CAN-кадр (≤6 байтів корисного навантаження), + суфікс кількості відповідей `" 1"`, якщо ELM його приймає. Запити фізично на ECM: `ATSH7E0`, фільтр `ATCRA7E8`, заголовки ввімкнені.
- Якщо група повертає не всі PID — автоматично переходить на один PID за запит.
- Швидкі PID щоциклу (якщо підтримуються): 06 STFT, 07 LTFT, 0C RPM, 04 LOAD, 10 MAF, 0B MAP, 11 TPS, 0D SPEED, 14 O2 B1S1 (або 34/24 широкосмуговий, якщо 14 немає), 44 задана λ.
  Повільні (усі за ~4 с, по одній групі на цикл): 05 ECT, 0F IAT, 0E випередження, 03 fuel status, 3C кат, 15 O2 B1S2, 43 абс. навантаження, 42 напруга ECU, 33 baro, 46 зовн. темп., 1F час роботи + `ATRV`.
- Очікувана частота по BT: ~2,5–4 повних цикли/с; симулятор ~6–7.
- Стійкість: flush кожного рядка, fsync кожні 5 с, автоперепідключення в той самий файл, ECU мовчить 10 циклів → реініціалізація.

## 2. Формат CSV

Файли `logs/elm_YYYYMMDD_HHMMSS.csv` + `.log` (події, позначки) + `.meta.json` (ELM, протокол, підтримувані PID, групи).

Колонки: `time_iso` (годинник ПК, мс), `t_s` (монотонні секунди від старту), `marker` (натиснута клавіша), `fuel` (gas/petrol/unknown), `ac` (on/off/unknown), `road` (highway/city/idle/unknown), `hz` (частота), далі PID-колонки: `rpm, maf, map, o2s1_v, o2s1_trim, wr1_lambda, cmd_lambda, stft, ltft, load, tps, speed, fuel_status (CL/OL_cold/OL_load/OL_fault/CL_fault), cat_temp, o2s2_v, abs_load, ecu_v, runtime, ect, iat, timing, baro, ambient, elm_v`. Повільні значення переносяться вперед до наступного оновлення. Набір колонок залежить від підтримуваних PID.

## 3. Аналізатор

```
python analyze.py                          # найновіший logs/elm_*.csv + stag/osc/**/*.osc, що перетинаються за часом
python analyze.py logs/elm_X.csv --osc a.osc b.osc
```
Результат: `analysis/<лог>/report.md` + PNG + CSV-таблиці.

Що рахує:
- **Фільтр валідних точок для тримів**: ECT ≥ 75 °C, fuel_status = CL, ≥ 20 с після перемикання палива, не накат.
- Режими: idle (v<3, rpm<1100), coast (TPS≈мін, v>10), accel (dv/dt>1 км/год/с), cruise (v≥15, |dv/dt|≤1).
- **Трими STFT+LTFT газ vs бензин** по режимах і на сітці оберти [500,1000,1500,2000,2500,3000,3500,4500,7000] × LOAD [0,20,30,40,50,60,80,101] (мін. 15 точок у клітинці). Висновок: |різниця| < 3 п.п. — ОК; від'ємна на газу = газ багатший.
- Лямбда: перетини 0,45 В (грубо — частота запису мала).
- ECT: час до 80 °C, мінімум на трасі (<80 → підозра на термостат).
- A/C: MAF/LOAD з A/C і без на тих самих швидкостях.
- **Оцінка витрати з MAF**: паливо = MAF / (AFR × λ_cmd), AFR газ 15.5 / бензин 14.7, густина 0.54 / 0.745 кг/л, накат з fuel cut = 0. Це «скільки треба двигуну»; фактична витрата більша → надлишок в open loop або похибка вимірювання.
- **Stag (.osc)**: зведення з ELM за часом (merge_asof, допуск 0,5 с); паливо береться зі статусу Stag; карта **D = (Б_бенз − Б_газ)/Б_бенз × 100** по оберти × MAP [0.15…1.05 бар], + список клітинок, упорядкованих за часом впорску Б (= вісь множника).
- **Трими газ − бензин по клітинках оберти × MAP з Б на бензині** (`trim_cells_by_ms.csv` + таблиця в звіті): Δ п.п., k = (1+TT_газ)/(1+TT_бенз) і «зміна точки, %» — це готова адреса й розмір правки множника. Клітинки навмисно ділені за обертами × MAP, **не за Б**: на багатій газовій карті Б на газу коротший і точки з'їжджали б у нижчі смуги (систематична похибка). Не пиши власний скрипт для цього — таблиця вже є.
- Тиск газу по навантаженню, просідання, порівняння з `--work-pressure`.

## 4. Парсер `.osc` і `.set`

```
python stag_osc.py файл.osc            # → файл.csv
python stag_osc.py --info файл.osc     # таблиця каналів, мін/макс
```
Колонки CSV: `time, t_s, map_bar, gas_p_bar, gas_temp_c, reducer_temp_c, internal_temp_c, rpm, supply_v, status, petrol_ms_1..N, gas_ms_1..N, lambda1_v, engine_temp_emul_c, ch_XX…, on_gas`. Формат — `osc-format.md`.

### Парсер `.set` (резервна копія налаштувань)

```
python stag_set.py файл.set              # записи параметрів і карта множника
python stag_set.py --diff a.set b.set    # що змінилось між двома копіями
python stag_set.py --dump файл.set       # розкодовані байти
```
Після «Ugic_Set» кожен байт XOR-нутий з попереднім; параметри — записи `id, len, 00 00 00, значення` (BE). Множник (точки «мс → x») звірено зі скріншотом. Які id відповідають яким полям AC STAG — **не розкладено**: id 07 = 120 / id 08 = 60 — імовірно робочий / мінімальний тиск ×100 бар, не підтверджено. Щоб розкласти — зберегти налаштування з демо-режиму AC STAG (значення відомі) і порівняти `--diff`.

## 5. Без машини

`python elm_logger.py --sim --sim-speed 10` — симулятор ECU Toyota з закладеною помилкою «газ переливає 6 %» (STFT+LTFT на газу ≈ −6 %). Аналізатор має показати це. Прогін із позначками: `--duration 200 --auto-markers "40:g,45:h,55:a,80:s,105:b,145:c,148:g,175:i,185:b"`.

## 6. Типові проблеми

| Симптом | Що робити |
|---|---|
| `no COM ports` | ELM не спарений (Windows: Bluetooth → Добавить → PIN 1234/0000); BLE-адаптери COM-порт не створюють |
| `ECU not answering on 0100` | запалювання вимкнене / ELM «заснув» — перевтикнути |
| `multi-PID … falling back` | клон не тягне мульти-PID — нормально, просто повільніше |
| `Hz < 1.5` | повільний клон; зменшити набір PID або `--single` не допоможе — прийняти |
| позначки не ставляться | фокус не на вікні логера |
| `.osc` не підхоплюється | файл не в `stag/osc/`, або час ноутбука змінювали, або інша прошивка → `stag_osc.py --info` |
